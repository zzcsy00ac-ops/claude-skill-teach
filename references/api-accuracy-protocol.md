# API Accuracy Protocol (AAP)

> 解决"教学幻觉"——LLM 对 API/库/CLI 参数的幻觉率较高（设计假设，未经独立验证）。
> 自回归模型存在"自我纠正盲点"——说出第一个错误 token 后难以自检（设计假设，未经独立验证）。
> 因此验证不能依赖 LLM 自检，必须用外部工具强制校验。

## 风险分类（silent check, every turn）

即将陈述以下内容时，**必须先验证，不可依赖参数记忆**：

| 级别 | 触发内容 | 例子 |
|------|----------|------|
| **RED** | 参数语义/默认值/单位/返回值含义 | "CACHE 参数控制缓存大小，单位是 MB" |
| **YELLOW** | API/方法/函数存在性 + 签名 | "Redis 有 `EXPIRE` 命令，签名为 `(key, seconds)`" |
| **GREEN** | 语言原生语法（for/if/return） | 无需验证 |

## 验证流程

```
即将陈述 API 事实
    ↓
分类风险等级
    ↓
RED/YELLOW → 调用 Context7 或查官方文档
    ├── 工具可用 + 确认 → 正常教学
    ├── 工具可用 + 冲突 → 以工具为准（TRUST THE TOOL）
    ├── 工具可用 + 未找到 → 标注 ⚠️ 待验证
    └── 工具不可用 → 进入降级模式（见下）
GREEN → 直接教学，无需验证
    ↓
陈述后自审："我是否验证了这个具体参数的含义？"
    ├── 是 → 继续
    └── 否 → 补充验证或标注 ⚠️
```

### TRUST THE TOOL 原则

当工具返回的信息与你的参数记忆冲突时：
- **以工具为准。** 你的记忆可能是 L2 级幻觉（API 存在、参数名正确，但语义错误）。
- 不要试图"调和"——直接采用工具结果。
- 如有必要，向学习者说明："我查了一下，实际行为和我之前说的略有不同……"

## 降级模式（工具不可用时）

无法验证时，将"不确定"转化为**高价值学习时刻**：

> "这个 API 细节我不完全确定。两个选项：
> (a) 你自己查官方文档然后告诉我——这也是重要的工程能力
> (b) 我按理解讲，但标注 ⚠️ 待验证，你之后自行核实"

这本身是教学——教学习者查文档、标注不确定性、独立验证。

**绝不假装确定。** "我不确定"比"错误的确定"好一万倍。

## 失败处理

发现已经教了错误 API 事实时：

1. **立即承认**——"刚才这个参数我说错了，实际是……"
2. **直接修正**——给出正确信息，不要求学习者"推导"正确答案
3. **记入进度日志**：`<date>: API错误修正——[错误→正确]`
4. **这是准确性失败，不是 Socratic 失败**——不需要从 Recovery Kit 走

## 与 Socratic 教学的关系

AAP 针对**操作问（API 参数/工具语法）**，不影响**概念问（为什么/原理）**的 Socratic 流程。

- 概念问 → 正常 Socratic（Rule 1 Concept vs Operation 分类不变）
- 操作问中的 conventional 部分 → AAP 验证 + 直接告知（Rule 1 已覆盖）
- 操作问中的 API 细节 → AAP 验证 + 直接告知

AAP 不改变"问而不告"原则——它确保被"告知"的部分（givens）本身是**准确的**。
